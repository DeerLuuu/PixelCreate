AI 画一只猫

PixelCraft 本地 AI 工具服务的真实实录：外部 AI 在 127.0.0.1 上通过 JSON 协议逐笔下笔，画完只是一步撤销。

画布 64×64 · 等距体素 · 7 帧（空白 → 躯干 → 尾巴 → 头 → 左耳 → 右耳 → 胸口）

每一笔是什么

    它是怎么发生的

    • 服务只绑 127.0.0.1，默认关闭，token 每次启动随机；写操作分三档（read / draw / all），破坏性工具默认一律拒绝（确认界面属后续期）。
    • 协议只有两个入口：GET /ai/health（版本 / 文档版本号 / 档位，由 TS 单源应答）与 POST /ai（list_tools、digest、read_region、call_tool、turn_begin/preview/commit/rollback、status）。
    • AI 不是"贴一张图"：它先 digest 读画布尺寸与包围盒，再用 iso_set 设参数、iso_origin 标落点、iso_generate 落笔，然后 read_region 把像素读回来核对 —— 画一笔、看一眼、再修一版，这次实录一共迭代了 9 轮。
    • 所有落笔都包在一个AI 回合里：整个过程中间不落历史，收尾时合成一条撤销记录。想丢掉这一轮就 turn_rollback，或者撤销一次。

    为什么是"体素猫"，不是像素画

    这一期的工具表里还没有像素笔刷（draw_path / fill / fx_* 属后续期），能落笔的只有等距体素工具。而 tile=4 时最小可画单元是 1×1×1 体素 = 6×5 像素，差不多是半张脸 —— 所以眼睛、胡须、表情都画不到能看的程度（试过，糊成一块）。最后靠"浅色头 + 深色躯干 + 双耳 + 尾巴 + 胸口浅块"把结构区分开。

    怎么复现

    # 1) 编译一次（宿主直接 require 编译产物）
node node_modules/typescript/bin/tsc -p tests/tsconfig.json

# 2) 起本地工具服务（会打印端口与随机 token）
node toolchain/ai-server.mjs --port 8787 --tier draw

# 3) 用带 token 的客户端按顺序发调用（序列见下面的 JSON）
curl.exe -s -H "Authorization: Bearer <token>" http://127.0.0.1:8787/ai/health

    这一轮完整的调用序列：下载 ai-demo-recipe.json（每一项就是一次 POST /ai，按顺序重放即可画出同一只猫）。

    它属于哪一块

    期内容
    C0文档文本化：docDigest / readRegion / applyOps
    C1工具表：48 个工具（read 4 / draw 38 / destructive 5 / ui 1）
    C2回合事务：一轮一条撤销、期间不写自动保存
    C3本地工具服务：TS 协议路由 + 开发宿主 + Android 端口服务（AiServer.java）
    后续C4 电脑侧 MCP 转发、C5 应用内助手与像素级绘图工具
