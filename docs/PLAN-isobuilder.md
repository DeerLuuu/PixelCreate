# 可行性方案：等距构建（IsoBuilder）

> 目标：评估把 Aseprite 扩展 **IsoBuilder**（三视图 → 等距像素画）的功能做进 PixelCraft 的可行性，
> 给出技术方案、分期计划、工作量与风险。
>
> 上游：[Aseprite Community 帖子](https://community.aseprite.org/t/extension-isobuilder-an-extension-for-creating-isometric-pixel-art/28612)
> （作者 HasuDelFuturo）、[itch 页面与用户指南](https://hasudelfuturo.itch.io/isobuilder)、
> 演示视频 [1](https://www.youtube.com/watch?v=OQsycHCA1Mc) / [2](https://www.youtube.com/watch?v=0FLeQS32IT4)。
> **该扩展没有公开源码**（itch 发布），本方案只按「功能等价」自行实现，不复制其代码与资源；
> 算法本身（三视图求视觉外壳 + 等距投影）是教科书内容，见 §3。

---

## 1. 结论

**可行，且和 PixelCraft 现有能力高度契合**：核心是三个纯函数（视觉外壳 / 等距投影 / 着色），
工作区与预览都能直接用现有画布、图层、覆盖层、历史栈，不需要新引擎能力。

| 项 | 结论 |
|---|---|
| 难度 | 中（难点在**像素几何口径**与**三视图对齐 UX**，不在算法） |
| 推荐路线 | **方案 A**：单画布 2×2 四宫格（FRONT / SIDE / TOP / PREVIEW），与原版一致 |
| MVP 范围 | 四宫格工作区 + 视觉外壳 + 2:1 等距渲染 + 三面着色（原始面颜色 / 默认等距色）+ 接触阴影 + 一条撤销 |
| 工作量 | v1 约 700–900 行实现 + 约 150 行测试（与「色彩明暗」同量级，一个开发轮次内可完成）；v2/v3 见 §6 |
| 差异化机会 | 原版**还没有**逐帧渲染、没有左右视角切换、没有实时预览 —— 这三条（尤其**逐帧 = 等距动画**）是 PixelCraft 能直接超车的地方 |
| 最大风险 | 视觉外壳的表达力上限（凹形 / 悬空 / 角色不精确，原版作者自己也承认）；对齐 UX（原版论坛有人反馈「看不懂怎么用」） |

## 2. 上游功能拆解（照论坛与截图还原）

原版工作流：**一张精灵被分成 2×2 四个象限**（截图见上游帖子），左上 FRONT、右上 SIDE、左下 TOP、
右下 PREVIEW，每个象限是「工作区尺寸」（可调）；三个视图里画好正交轮廓后点 **Render**，
在 PREVIEW 象限生成**一个可编辑的普通图层**（非破坏：可以继续画、可以复制走）。

| 功能 | 说明 | 我们做不做 |
|---|---|---|
| 三视图 → 等距预览 | FRONT / SIDE / TOP 三个正交轮廓合成等距图 | ✅ v1 |
| 工作区尺寸可调 | 每个象限的边长 | ✅ v1 |
| 预览是可编辑图层 | 生成完就是普通像素，不是只读浮层 | ✅ v1（写进新建的 `iso` 图层） |
| 原始面颜色 / 默认等距色 | 顶面取 TOP 视图的色，或用固定三档明暗 | ✅ v1（默认等距色直接复用 `engine/shading.ts`） |
| 自动阴影 | 物体在地面上的投影 | ✅ v1 做接触阴影，v2 做方向投影 |
| 逐帧渲染 | 让等距图跟着动画逐帧生成 | ❌ 原版没有 → **我们 v3 做** |
| 左右视角切换 | 生成左视 / 右视两种朝向 | ❌ 原版只在待办 → **我们 v2 做** |
| 实时预览 | 边画边更新等距图 | ❌ 原版认为要靠独立窗口 → 我们用多画布方案（v3） |

## 3. 原版怎么算的（我们的实现原理）

### 3.1 三个视图的坐标口径

设工作区每象限 `W×H`（下面用 `W = H = N`）。约定（写死在文档与提示里，避免用户对不齐）：

| 视图 | 横轴 | 纵轴 | 对应三维轴 |
|---|---|---|---|
| TOP（俯视） | `x`（向右） | `y`（向下 = 深度） | 地面格 `(x, y)` |
| FRONT（正视） | `x`（与 TOP 的 x 对齐） | 高度（画布上方 = 高） | `(x, z)`，`z` 从地面往上 |
| SIDE（侧视） | 深度 `d` | 高度 | `(d, z)`，`d` 与 TOP 的 `y` 对齐（左视时 `d = N-1-y`） |

### 3.2 视觉外壳（visual hull）

三个视图都是「正交剪影」，把它们各自拉伸成三维体再求交集：

```
solid(x, y, z) = top(x, y) && front(x, z) && side(d(y), z)
```

- `top(x,y)`：俯视图该格是否被画（有空隙自动成为凹陷）；
- `front(x,z)`：正视 x 列在高度 z 是否有像素（`z` 由画布 y 翻过来）；
- `side(d,z)`：侧视同理；
- 「有像素」的判定加一个**透明度阈值**（默认 `alpha > 0`，可调 0–255 用于吃掉抗锯齿边缘）。

这一步是纯函数、`O(N³)`：`N = 32` 时 32768 次布尔运算，远低于一帧预算。

### 3.3 等距投影与像素几何（**需要先 spike 定死**）

像素画惯例是 **2:1**（菱形的宽高比 2:1，≈26.57°，不是真等距的 30°）：

```
sx = (x - y) * (T/2)
sy = (x + y) * (T/4) - z * ZH
```

取 `T = 4`（每个地面格占 4×2 像素）、`ZH = 1`（每单位高度 1 像素）：

```
sx = (x - y) * 2      // 整数
sy = (x + y) * 1 - z  // 整数
```

于是「一个体素」在屏幕上是：**顶面 2 px 宽的菱形 + 两个 1 px 高的侧面**，
一个立方体的外接框是 4 px 宽 × 3 px 高（顶 2×1 + 侧面 1 高 + …），与 `ws1.png` 截图里的观感一致。

> ⚠️ 注意：PixelCraft 现有的等距**网格辅助线**是真实 30°（`src/render/view.ts` 的 `drawIsoGuide()`），
> 而等距**渲染**必须用 2:1。两个口径并存会让用户困惑 → 工作区里由构建器自己画 2:1 的对齐线，
> 不依赖网格设置（或给网格加一档「2:1 等距」）。

### 3.4 绘制顺序（画家算法）

按深度递增绘制：先 `x + y` 小的（远），同一深度内先画 `z` 小的（下），每个体素按
**顶面 → 右面(+x，用 FRONT 的色) → 左面(-y，用 SIDE 的色)** 顺序 stamp。
`(x + y, z)` 的排序保证了近处体素覆盖远处，不会出现互相盖错。

### 3.5 着色

| 模式 | 顶面 | 右面（+x，朝前） | 左面（-y，朝侧） |
|---|---|---|---|
| **原始面颜色**（默认） | 取 `top(x,y)` 的色 | 取 `front(x,z)` 的色 | 取 `side(d,z)` 的色 |
| **默认等距色** | 基色最亮档 | 基色中间档 | 基色最暗档 |

「默认等距色」直接复用上一轮做的 `engine/shading.ts` 的 `shade` 行（强度 / 亮度峰值 / 温度可调），
不必新写明暗算法 —— 这也是把它接进同一套参数面板的理由。

### 3.6 自动阴影

- **v1 接触阴影**：取 `top` 的轮廓，在预览里向下偏移 1–2 px 画半透明暗色（在物体之前绘制）。
- **v2 方向投影**：按光照方向（8 档）把轮廓沿地面逐格推进，越远越淡（`alpha` 递减），
  与地平线接触处最深 —— 参考截图里机器下方那圈软阴影。

## 4. 与 PixelCraft 现有能力的映射

| 需要的能力 | 现有实现 | 结论 |
|---|---|---|
| 一张画布切四象限 | 画布就是普通位图，象限只是坐标区间 | 新增纯函数 `isoQuadrants(w, h)` 算四个矩形 |
| 覆盖层画分隔线与标签 | `src/render/view.ts` 的 `drawOverlay()`，已有缓存画法（`isoCache` / `drawIsoGuide`） | 加 `drawIsoWorkspace()`，同样的缓存套路 |
| 渲染结果落成一层 | `Session.layerAdd()` + `Cel` 写像素 + `history.pushPixels/pushStruct` | 一次渲染 = 一条历史 |
| 非破坏编辑 | 预览就是普通图层 | 零改动 |
| 默认等距色 | `engine/shading.ts`（`shadingRamps` 的 `shade` 行） | 直接复用 |
| 面板与设置 | `src/ui/kit` 的 Dialog / Row / Switch / NumberField / ChipGroup | 照「色彩明暗」的写法 |
| 面板入口 | 调色板面板 + 主菜单 + `pc-*` 事件 → `App.tsx` 的 `Keep` | 照 `openShading()` 的写法 |
| 逐帧（v3） | `doc.frames` + `Session.applyFrame` | 对每帧跑一遍渲染即可 |
| 三画布联动（v3） | 多画布空间 + 引用画布（`Session.refPixels()` 已经能读源画布像素） | 方案 B 的可行性来源 |
| 导出 | 预览就是像素，PNG / 精灵表 / GIF 原样可用 | 零改动 |

## 5. 技术方案（推荐：方案 A，单画布四宫格）

### 5.1 数据模型

```ts
// src/engine/iso.ts（新，纯函数）
interface IsoConfig {
  quad: number;              // 每象限边长（8..128）
  view: "right" | "left";    // 侧视图方向（v2 起步，v1 固定 right）
  colors: "face" | "shade";  // 原始面颜色 / 默认等距色
  alphaMin: number;          // 视为实体的最小 alpha（0..255）
  shadow: "off" | "contact"; // v1；v2 加 "project"
  shadowDir: 0|1|2|3|4|5|6|7;// v2
  shade: ShadingParams;      // colors === "shade" 时的明暗参数
}
isoQuadrants(w, h): { front: Rect; side: Rect; top: Rect; preview: Rect }
isoHull(front, side, top, o: { quad, view, alphaMin }): Uint8Array   // N³ 体素
isoRender(hull, views, w, h, o: IsoConfig): { px: Uint8ClampedArray; w; h; box } // 只画到外接框
isoContactShadow(...): void                                          // 叠到同一个缓冲
```

### 5.2 会话与 UI

- `Session`：`isoConfig`（持久化到 prefs，跟 `shadingParams` 之类同级）、
  `newIsoWorkspace(quad)`（新建一张 `2N×2N` 画布 + 建 `iso` 图层 + 打开工作区模式）、
  `renderIso()`（读三视图 → 计算 → 清空并写入 `iso` 图层 → 一条历史 → 提示用了多少体素 / 多少像素）。
- `View`：`isoWorkspace`（`{ quad } | null`），覆盖层画四宫格边框、象限标签（FRONT / SIDE / TOP / PREVIEW）、
  以及三条对齐辅助线（TOP 的 x/y 轴延长到 FRONT / SIDE 的对应行列）；进入工作区时把视图适配到整张画布。
- `IsoModal`（`src/ui/iso-modal.tsx`，不再往 2000 行的 `modals.tsx` 里塞）：
  - 第一段「工作区」：象限边长、新建工作区按钮、辅助线开关；
  - 第二段「渲染」：视角、颜色模式（chips）、明暗参数（复用色彩明暗的四个数值 + 两个温度）、
    实体 alpha 阈值、阴影；
  - 第三段：渲染 / 清除预览 / 把预览存成新图层；底部一行说明「渲染只覆盖 `iso` 图层，其它图层不动」。
- 入口：主菜单 + 画布球「等距构建」（与「高级缩放」「色彩明暗」同级），`openIso()` 派发 `pc-iso`
  由 `App.tsx` 收面板开弹窗（照 `pc-shading` 的现成写法）。

### 5.3 方案 B（可选，v3）：四张画布 + 引用画布

把 FRONT / SIDE / TOP 各放一张画布（吸附成组），预览画布用**引用画布**指向它们，
渲染时用 `Session.refPixels()` 读源像素、写到预览画布。好处是「边画边看」的实时联动几乎白拿；
代价是跨画布坐标对齐、历史与吸附组合更复杂。**建议 v1 不做**，等方案 A 的口径被真机验证过再上。

## 6. 分期计划与验收标准

### v1（MVP，建议先做）

1. `engine/iso.ts`：`isoQuadrants` / `isoHull` / `isoRender`（含接触阴影）+ 单测。
2. `Session.newIsoWorkspace` / `renderIso` / `isoConfig` 持久化。
3. `View.drawIsoWorkspace`（四宫格 + 标签 + 对齐线）。
4. `IsoModal` + 入口 + i18n（中英各一套 `iso.*`）+ `.dlg-iso` / `.iso-*` 样式（进 ui-tokens 的 SHELL）。
5. 文档：`docs/API.md` 新增 §6d（引擎）与 §17.1 组件行；README 功能表一行；更新日志一条。

**验收（可自动断言）**

- 单格立方体（三视图各 1 格）→ 预览的顶面菱形与两个侧面像素坐标等于黄金值；
- 遮挡：深度 `x+y` 大的格子覆盖小的；
- 颜色：`colors: "face"` 时三面分别等于三个视图对应位置的色；`"shade"` 时顶面明度 > 正面 > 侧面；
- 阴影：`shadow: "contact"` 时物体外接框下方多出暗色像素，`"off"` 时没有；
- 历史：一次渲染只压一条，`undo` 后 `iso` 图层回到渲染前；
- 非破坏：渲染后仍可在 `iso` 图层上继续画；重复渲染只覆盖该图层；
- 性能：`N = 32` 的 hull + render < 16 ms（纯函数基准，node 直接跑）；
- 面板 SSR 冒烟 + i18n 键校验 + 令牌测试全绿。

### v2（体验补齐）

方向投影阴影（8 档光照）、左 / 右视角切换、四象限各自尺寸、面板内小预览（不是实时，是「点渲染前先看」）、
稀疏体素优化（只遍历有内容的包围盒）、「把预览另存为新图层」与「导出预览 PNG」。

### v3（差异化）

**逐帧渲染**（每帧跑一遍 → 直接出等距动画，原版没有）、方案 B 的实时联动（四画布 + 引用画布）、
6 向旋转（同一 hull 绕 z 轴 90° 生成 4 向 + 左右视角 = 8 向）、等距精灵表导出、
引导步骤（`src/app/guide.ts` 加一步「等距构建」真操作演示）。

## 8. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 视觉外壳表达力有限 | 凹形、悬空、角色细节会失真（原版作者也承认「对角色不是完整方案」） | 说明书写清楚；提供「把预览当参考底图」的用法（上游截图里就是这么画角色的）；v2 再考虑「逐层 hull」（每个图层各算一次） |
| 三视图对不齐 | 原版论坛有人反馈「很困惑、没有手册」 | 我们把对齐做进产品：覆盖层画三条对齐辅助线 + 象限标签 + 首次进入的一次性提示；`guide.ts` 加一步 |
| 像素几何选错返工 | 2:1 / 30° / 体素尺寸一旦定错，整体重做 | 先做 spike 用单格立方体锁死口径；把 `T` / `ZH` 做成常量并写进文档 |
| 性能 | `N³` 外壳 + 每体素 3 像素 stamp | 只在点「渲染」时算；先算包围盒再遍历；`N ≤ 64` 时上限约 26 万体素，仍在预算内 |
| 历史与撤销 | 渲染是「清空 + 写入」的一大片像素 | 用 `history.pushPixels`（差分）或 `pushStruct`，保证一条撤销；渲染前若 `iso` 图层有内容，提示会被覆盖 |
| 与现有 iso 网格混淆 | 网格辅助线是真 30°，渲染是 2:1 | 工作区里由构建器画自己的对齐线；或给网格加一档「2:1 等距」（顺手修一个长期的不一致） |
| 许可证 | IsoBuilder 无公开源码 | 只做功能等价、独立实现；在文档与更新日志里署名灵感来源（与 Color Shading v5.0 的做法一致） |

## 10. 建议的第一步

先做 §3.3 的 **spike**：写 `engine/iso.ts` 的 `isoHull` + `isoRender` 两个纯函数，
用「单格立方体 / L 形 / 带空洞」三个黄金用例把像素口径钉死（约半小时，node 里直接跑），
口径确定后再往 UI 与覆盖层上接 —— 这样返工风险最低，也方便先给你看一张生成图再决定要不要继续。
