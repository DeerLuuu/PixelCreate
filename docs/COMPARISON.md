# PixelCraft · Aseprite · Resprite 对比与锐评

> 生成时间：随项目迭代更新
> 目的：客观对比本项目（PixelCraft）与行业标杆 Aseprite、移动端商业软件 Resprite 的差异，并给出对本项目的犀利复盘与改进优先级。

---

## 一、三款工具定位

| 维度 | **PixelCraft（本项目）** | **Aseprite** | **Resprite** |
|---|---|---|---|
| 平台 | 移动 WebView / 网页（自研无 Gradle APK） | 桌面 Win/macOS/Linux（Steam） | 移动 iOS / Android App |
| 收费 | 免费开源 | 付费（Steam / 官网） | 订阅制 |
| 定位 | 触屏像素画快速创作 | 行业标准·全能编辑器 | 移动端商业像素画「工作室」 |
| 目标用户 | 手机随手画、自用 / 移植作品 | 专业、独立游戏美术 | 移动端创作者 |

**一句话**：Aseprite 是「正统」，Resprite 是「移动端商业竞品」，PixelCraft 是「把 Aseprite 像素算法搬到触屏的免费移植/自用工具」。

---

## 二、功能维度对比

| 功能 | PixelCraft | Aseprite | Resprite |
|---|---|---|---|
| 笔刷 / 形状 | 铅笔·橡皮·填充·形状·魔棒；笔刷为 Aseprite 半径栅格，椭圆/圆用 **Zingl 源码 1:1** | 同类且更全面（压力、纹理、自定义笔刷） | 移动端主流齐全 |
| 对称 | **可旋转对称轴（0/45/90/135）+ 锁定 + 四向**，比 Aseprite 固定镜像更灵活 | 竖/横/对角镜像 | 基础镜像 |
| 变换 | 移动 / 旋转 / 缩放（Aseprite 仿射复刻） | 更多（含变换细节） | 有 |
| 图层 / 帧 | 基础图层 + 帧 | **帧标签、循环区间、多选、成组、裁剪/参考/遮罩层** | 较全 |
| 时间轴 | 洋葱皮基本；**默认隐藏、无缩略图、无拖拽重排、无标签/loop** | 成熟 | 较全 |
| 调色板 | 色板 + HSV + 取色 | **量化、降色、抖动、图像取色板** | 有 |
| 特效 | 描边 / 投影 / 外发光 / 反色 / 灰度 / 居中 / 智能裁剪 | 滤镜更全（扭曲/旋转/色相分离等） | 一般 |
| 导出 | PNG / 精灵表 / GIF | **ASE 格式、WebP、APNG、JSON 数据、tilemap** | PNG/GIF |
| 互操作 | **自定义 `.pxc`，无法读写 `.aseprite`** | 事实标准 | 一般 |
| 脚本 / 自动化 | **无** | **Lua 脚本 + CLI** | 无 |
| Tilemap | **无** | **图块层 / 图块集** | 无 |
| 桌面体验 | **无快捷键、无右键菜单、无多文档** | 成熟 | 移动端为主 |
| 上手 / 发现性 | 触屏球/停靠/圆片，**发现性差、无引导** | 按钮多但成熟 | 移动端顺手 |

## 三、锐评：PixelCraft 的痛点与缺点

### 1. 性能是最大瓶颈（硬伤）
`onMove → session.repaint() → markDirty() → buildComposite()` 每次笔迹移动都**全量重算整帧所有图层 + 洋葱皮**。
- 128×128 勉强；**256/512×512 + 多图层会卡**；
- 无脏矩形、无增量缓存、无 Web Worker、无 rAF 节流。

> 做稍大的像素画会立刻撞墙，这是全线体验的底层约束。

### 2. 生态锁死（互操作硬伤）
- 自研 `.pxc`，**不能读/写 `.aseprite`**；
- 导入仅 PNG / GIF / 精灵表；无 WebP / APNG / JSON 数据导出；
- 与团队、社区、既有 Aseprite 项目协作基本不可能，只能「自娱自乐」。

### 3. 桌面 / 网页端体验缺失
- `App.tsx` 中**零 `keydown`**：无 Ctrl+Z/Y、无 B/E/G/P 切工具、无 Ctrl+S、无 `[]` 调笔刷、无空格平移；
- 整个 UI 是**触屏范式**（魔法球 / 停靠区 / 圆片 / 长按），鼠标操作别扭；
- 大量功能埋在天球 / 子菜单里，**发现性极差、无新手引导**。

### 4. 功能「有但没做完」
- 变换：无透视、无浮层独立编辑、松手即落盘；
- 帧 / 层：**无标签 / 循环区间、无多选、无拖拽重排、无成组、无缩略图**；
- 调色板：无量化 / 降色 / 抖动、无图像取色板；
- 无 tilemap、无 Lua 脚本、无参考 / 裁剪层。

### 5. 数据安全薄弱
- 自动保存塞在 `localStorage`（>4MB **直接跳过**并弹提示）；
- 工程只有一份 + 自动保存，**无文件级备份 / 崩溃恢复**；
- 清 localStorage 数据全丢 → 「薛定谔的存档」。

### 6. 代码架构是「屎山雏形」
- `view.ts` 1300+ 行：手势 / 渲染 / 变换 / 对称全混在里面；
- `App.tsx` 900 行：魔法球 / 停靠 / 菜单 / 设置全塞；
- `session.ts` 是**上帝对象**；
- **UI 层几乎零测试**，仅引擎少量单测；改一个功能牵一发动全身，长期维护成本高。

### 7. 细节糙
- 大量操作**静默失败**（空状态 toast 是后补的）；
- 无障碍 / 可访问性基本没有（ARIA、小屏适配、减少动效）；
- 单文档、无 Tab。

---

## 四、一句话总结

**PixelCraft 在「把 Aseprite 的像素算法搬到触屏」这件事上做得很好（笔刷 / 椭圆 / 对称甚至反超），但在「成为一个能替代 Aseprite / Resprite 的完整工具」上，卡在五个位置：性能、互操作、桌面体验、生态（脚本 / tilemap）、代码可维护性。**

当前更像 **移动端轻量自用 / 移植作品**；要「能打」还需补齐：

## 五、改进优先级（建议路线）

| 优先级 | 事项 | 价值 |
|---|---|---|
| 🔥 高 | ① 绘画渲染增量优化（脏矩形 / 增量缓存 / rAF 节流 / 笔迹画到 overlay） | 大画布不卡，全局手感 |
| 🔥 高 | ② 键盘快捷键（Ctrl+Z/Y、工具切换、保存、空格平移）+ 桌面 UI | 网页端立刻好用 |
| 🔥 高 | ③ `.aseprite` / 标准格式读写 | 打破生态锁死 |
| ⚖️ 中 | ④ 帧标签 / 循环区间、图层/帧多选与拖拽重排 | 编缉效率 |
| ⚖️ 中 | ⑤ 调色板量化 / 降色 / 图像取色板 | 专业像素画 |
| ⚖️ 中 | ⑥ 数据安全：文件级备份、超出容量提示、崩溃恢复 | 可信度 |
| 🧭 低 | ⑦ 新手引导、空状态完善、无障碍 | 体验软性提升 |

> 已针对部分条目落地：空状态 toast、缩放指示 + 适配视图、保留视口、边缘自动平移（可开关、限速）、对称线锁定按钮远离画布、停靠区布局持久化等。
